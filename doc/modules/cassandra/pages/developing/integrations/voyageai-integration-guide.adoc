= Voyage AI by MongoDB Integration Guide for Apache Cassandra Vector Search
:page-layout: basic
:description: Complete guide to integrating Voyage AI by MongoDB embeddings with Apache Cassandra vector search capabilities.

Apache Cassandra's vector search capabilities follow a Bring Your Own Embeddings (BYOE) model, allowing you to use any embedding generation service. This guide demonstrates how to integrate Voyage AI by MongoDB's state-of-the-art embedding models with Cassandra for powerful semantic search applications.

NOTE: Voyage AI is now part of MongoDB. The product is referred to as *Voyage AI by MongoDB*; the API, `voyageai` Python package, and model names are unchanged.

== Overview

Voyage AI by MongoDB provides high-quality text embeddings optimized for retrieval and semantic search. Combined with Cassandra's SAI (Storage Attached Index) vector search, you can build scalable, low-latency similarity search applications.

=== Why Voyage AI by MongoDB + Cassandra?

* **High-Quality Embeddings**: Voyage AI by MongoDB's models (voyage-4, voyage-4-lite, voyage-4-large) are optimized for retrieval tasks
* **Flexible Dimensions**: Support for 256, 512, 1024, and 2048 dimensional embeddings
* **Scalable Storage**: Cassandra handles billions of vectors with horizontal scaling
* **Low-Latency Search**: SAI indexes provide fast Approximate Nearest Neighbor (ANN) search
* **BYOE Model**: Generate embeddings externally, store and search in Cassandra

== Prerequisites

Before starting, ensure you have:

* Apache Cassandra 5.0+ with vector search support
* Python 3.9 or higher
* Voyage AI by MongoDB API key (obtain from https://dash.voyageai.com/api-keys)
* Basic familiarity with CQL (Cassandra Query Language)

== Architecture Overview

The integration follows this workflow:

[source,text]
----
1. Application generates text/content
2. Voyage AI by MongoDB API converts to embeddings (float vectors)
3. Cassandra stores vectors alongside original data
4. SAI indexes enable fast similarity search
5. Queries return semantically similar results

== Step-by-Step Integration

=== Step 1: Initialize Voyage AI by MongoDB Client

[source,python]
----
import os
import voyageai

# Initialize client (automatically uses VOYAGE_API_KEY env var)
vo = voyageai.Client(api_key=os.getenv("VOYAGE_API_KEY"))

# Choose your model
MODEL = "voyage-4-lite"  # Options: voyage-4, voyage-4-lite, voyage-4-large, voyage-code-4 (see "Choose the Right Model")
DIMENSION = 1024  # Options: 256, 512, 1024, 2048 (voyage-finance-2 and voyage-law-2: 1024 only)
----

=== Step 2: Generate Embeddings

[source,python]
----
# Single text embedding
texts = ["Apache Cassandra is a distributed NoSQL database"]
result = vo.embed(
    texts=texts,
    model=MODEL,
    input_type="document",  # or "query" for search queries
    output_dimension=DIMENSION
)

embeddings = result.embeddings  # List of float arrays
total_tokens = result.total_tokens  # Token count for billing
----

==== Batch Processing

Voyage AI by MongoDB supports batch embedding generation with these limits:

* Maximum 1,000 texts per request, for every model
* Total tokens per request vary by model:
** `*-lite` models (voyage-4-lite, voyage-3.5-lite): 1M tokens
** voyage-4, voyage-3.5: 320K tokens
** voyage-4-large, voyage-3-large, voyage-code-3, voyage-finance-2, voyage-law-2: 120K tokens
** voyage-code-4: no total token limit is documented; only the 1,000-texts limit applies
* Contextualized and multimodal models have their own limits, described in their sections below

===== Simple Count-Based Batching

[source,python]
----
# Basic batch processing example (NOT RECOMMENDED for production)
documents = [
    "First document text...",
    "Second document text...",
    # ... up to 1000 documents
]

batch_size = 128
all_embeddings = []

for i in range(0, len(documents), batch_size):
    batch = documents[i:i + batch_size]
    result = vo.embed(texts=batch, model=MODEL, input_type="document")
    all_embeddings.extend(result.embeddings)
----

WARNING: Count-based batching can cause API errors if documents exceed token limits. See Token-Aware Batching below for the recommended approach.

===== Token-Aware Batching (Recommended)

For production use, implement token-aware batching to prevent API errors and maximize batch utilization. This approach uses actual token counts instead of document counts.

[source,python]
----
import os
from typing import List, Generator

import voyageai
# Pure helpers from examples/PYTHON/voyageai_batching.py (no dependencies):
#   VOYAGE_TOKEN_LIMITS - explicit total tokens per request, by model
#   token_limit_for()   - raises ValueError for a model that is not listed
#   plan_batches()      - groups input indexes by token total and input count
from voyageai_batching import MAX_INPUTS_PER_REQUEST, plan_batches, token_limit_for


class TokenAwareBatchProcessor:
    """Process embeddings with token-aware batching."""

    def __init__(self, client: voyageai.Client, model: str):
        self.client = client
        self.model = model
        # None means: no documented total token limit (voyage-code-4)
        self.max_tokens = token_limit_for(model)

    def build_token_batches(self, texts: List[str]) -> Generator[List[str], None, None]:
        """Build batches based on actual token counts, in input order."""
        if not texts:
            return

        # Count tokens with the SDK tokenizer. tokenize() makes no Voyage API
        # call and costs nothing; the model's tokenizer is downloaded from
        # Hugging Face on first use and cached.
        all_token_lists = self.client.tokenize(texts, model=self.model)
        token_counts = [len(tokens) for tokens in all_token_lists]

        # Raises ValueError if a single text is above the token limit.
        for group in plan_batches(token_counts, self.max_tokens, MAX_INPUTS_PER_REQUEST):
            yield [texts[i] for i in group]

    def embed_with_token_batching(
        self,
        texts: List[str],
        input_type: str = "document",
        dimension: int = 1024
    ) -> List[List[float]]:
        """Embed texts using token-aware batching."""
        all_embeddings = []

        for batch in self.build_token_batches(texts):
            result = self.client.embed(
                texts=batch,
                model=self.model,
                input_type=input_type,
                output_dimension=dimension
            )
            all_embeddings.extend(result.embeddings)

        # Batches are contiguous and in input order, so the vectors are in
        # the same order as `texts`.
        return all_embeddings

# Usage example
vo = voyageai.Client(api_key=os.getenv("VOYAGE_API_KEY"))
processor = TokenAwareBatchProcessor(vo, "voyage-4")

# Process documents with automatic token-aware batching
documents = ["Document 1 text...", "Document 2 text...", ...]  # Any number of documents
embeddings = processor.embed_with_token_batching(documents, input_type="document")
----

**Benefits of Token-Aware Batching:**

* **Prevents API Errors**: Automatically respects the model's total token limit and the 1,000-texts-per-request limit
* **Maximizes Utilization**: Creates largest possible batches without exceeding limits
* **Order Preserving**: Batches are contiguous slices of the input, so vectors come back in input order
* **Explicit Limits**: An unknown model or a single text above the token limit raises an error instead of guessing

**How It Works:**

1. Calls `client.tokenize()` once to get token counts for all documents (this is not a Voyage API call and costs nothing; the tokenizer is downloaded from Hugging Face on first use and cached)
2. `plan_batches()` builds batches that stay within the model's token limit and at most 1,000 texts
3. Uses Python generators for memory efficiency
4. Automatically adjusts batch sizes based on content

For a complete working example, see `examples/PYTHON/voyageai-cassandra-example.py` (Example B: Token-Aware Batching). The batching logic is in `examples/PYTHON/voyageai_batching.py`, with failure-mode tests in `examples/PYTHON/test_voyageai_batching.py`.

=== Step 3: Create Cassandra Schema

==== Create Keyspace

[source,cql]
----
CREATE KEYSPACE IF NOT EXISTS vector_search_demo
WITH REPLICATION = {
    'class': 'SimpleStrategy',
    'replication_factor': 1
};
----

For production, use `NetworkTopologyStrategy`:

[source,cql]
----
CREATE KEYSPACE IF NOT EXISTS vector_search_demo
WITH REPLICATION = {
    'class': 'NetworkTopologyStrategy',
    'datacenter1': 3
};
----

==== Create Table with Vector Column

[source,cql]
----
USE vector_search_demo;

CREATE TABLE IF NOT EXISTS products (
    product_id UUID PRIMARY KEY,
    name TEXT,
    description TEXT,
    category TEXT,
    price DECIMAL,
    description_vector VECTOR<FLOAT, 1024>,
    created_at TIMESTAMP
);
----

The `VECTOR<FLOAT, dimension>` type stores floating-point vectors. Ensure the dimension matches your Voyage AI by MongoDB output dimension.

==== Create SAI Vector Index

[source,cql]
----
CREATE CUSTOM INDEX IF NOT EXISTS products_vector_idx
ON products(description_vector)
USING 'StorageAttachedIndex'
WITH OPTIONS = {
    'similarity_function': 'COSINE'
};
----

Similarity function options:

* `COSINE`: Cosine similarity (recommended for normalized embeddings)
* `DOT_PRODUCT`: Dot product similarity
* `EUCLIDEAN`: Euclidean distance

An ANN query that also filters with `WHERE` needs an SAI index on every filtered column; without it Cassandra rejects the query with `ANN ordering by vector requires all restricted column(s) to be indexed`. Create these indexes if you use the filtered queries shown later in this guide:

[source,cql]
----
CREATE CUSTOM INDEX IF NOT EXISTS products_category_idx
ON products(category)
USING 'StorageAttachedIndex';

CREATE CUSTOM INDEX IF NOT EXISTS products_price_idx
ON products(price)
USING 'StorageAttachedIndex';
----

=== Step 4: Insert Data with Embeddings

[source,python]
----
from cassandra.cluster import Cluster
from datetime import datetime
from decimal import Decimal
import uuid

# Connect to Cassandra
cluster = Cluster(['127.0.0.1'])
session = cluster.connect('vector_search_demo')

# Prepare data
product = {
    "name": "Wireless Headphones",
    "description": "Premium headphones with noise cancellation and 30-hour battery",
    "category": "Electronics",
    "price": Decimal("199.99")
}

# Generate embedding
embedding_result = vo.embed(
    texts=[product["description"]],
    model="voyage-4-lite",
    input_type="document",
    output_dimension=1024
)
embedding = embedding_result.embeddings[0]

# Insert into Cassandra. The Python driver binds `?` markers only in
# prepared statements, so prepare the statement first.
query = session.prepare("""
INSERT INTO products (
    product_id, name, description, category, price,
    description_vector, created_at
) VALUES (?, ?, ?, ?, ?, ?, ?)
""")

session.execute(
    query,
    (
        uuid.uuid4(),
        product["name"],
        product["description"],
        product["category"],
        product["price"],
        embedding,
        datetime.utcnow()
    )
)
----

=== Step 5: Perform Vector Similarity Search

==== Basic ANN Query

[source,python]
----
# Generate query embedding
query_text = "noise cancelling headphones for music"
query_result = vo.embed(
    texts=[query_text],
    model="voyage-4-lite",
    input_type="query",  # Use "query" for search queries
    output_dimension=1024
)
query_vector = query_result.embeddings[0]

# Search for similar products
query = session.prepare("""
SELECT
    product_id,
    name,
    description,
    price,
    similarity_cosine(description_vector, ?) AS similarity
FROM products
ORDER BY description_vector ANN OF ?
LIMIT 5
""")

rows = session.execute(query, (query_vector, query_vector))

for row in rows:
    print(f"{row.name} - Similarity: {row.similarity:.4f}")
----

==== Understanding the Query Syntax

* `ORDER BY description_vector ANN OF [vector]`: Performs Approximate Nearest Neighbor search
* `similarity_cosine(description_vector, ?)`: Computes cosine similarity score
* `LIMIT 5`: Returns top 5 most similar results

. **Match Dimensions Exactly**
+

+

* Use `EUCLIDEAN` only if specifically required by your use case

+
For large initial data loads, consider creating the index after inserting data to improve performance.

+

== Performance Considerations

=== Embedding Generation Performance

* Voyage AI by MongoDB API latency: ~100-500ms depending on batch size
* Batch size: use token-aware batching (see above); larger batches mean fewer requests
* Concurrent requests: Use connection pooling for parallel processing

=== Cassandra Query Performance

* ANN query latency: 10-100ms depending on dataset size
* Index memory usage: ~4 bytes × dimension × row count
* Recommended maximum vectors per node: 10-100 million

=== Optimization Tips

. **Dimension Reduction**
+
Consider using lower dimensions (512 or 256) if 1024 is unnecessary:
+
[source,python]
----
result = vo.embed(texts=texts, model="voyage-4-lite", output_dimension=512)
----

. **Parallel Processing**
+
Generate embeddings in parallel using thread pools:
+
[source,python]
----
from concurrent.futures import ThreadPoolExecutor

def embed_batch(batch):
    return vo.embed(texts=batch, model=MODEL)

with ThreadPoolExecutor(max_workers=4) as executor:
    futures = [executor.submit(embed_batch, batch) for batch in batches]
    results = [f.result() for f in futures]
----

. **Connection Pooling**
+
Configure Cassandra driver connection pooling:
+
[source,python]
----
from cassandra.cluster import Cluster
from cassandra.policies import DCAwareRoundRobinPolicy

cluster = Cluster(
    contact_points=['127.0.0.1'],
    load_balancing_policy=DCAwareRoundRobinPolicy(local_dc='datacenter1'),
    protocol_version=5
)
----

== Troubleshooting

=== Common Issues and Solutions

==== Issue: "Dimension mismatch" error

*Problem*: Vector dimension doesn't match table definition.

*Solution*: Ensure Voyage AI by MongoDB `output_dimension` matches your `VECTOR<FLOAT, N>` definition:

[source,python]
----
# Match these values
DIMENSION = 1024
result = vo.embed(texts=texts, model="voyage-4-lite", output_dimension=DIMENSION)

# CQL table definition
# description_vector VECTOR<FLOAT, 1024>
----

==== Issue: Voyage AI by MongoDB rate limit errors

*Problem*: Exceeding API rate limits.

*Solution*: Implement exponential backoff and reduce request frequency:

[source,python]
----
import time

def generate_with_backoff(texts, max_retries=3):
    for attempt in range(max_retries):
        try:
            return vo.embed(texts=texts, model=MODEL)
        except voyageai.error.RateLimitError:
            if attempt == max_retries - 1:
                raise
            wait_time = 2 ** attempt
            time.sleep(wait_time)
----

==== Issue: Slow query performance

*Problem*: Vector searches taking too long.

*Solutions*:

* Verify SAI index exists: `DESCRIBE INDEX products_vector_idx`
* Reduce `LIMIT` value in queries
* Consider using lower dimension embeddings
* Ensure adequate Cassandra cluster resources

==== Issue: API key not found

*Problem*: `VOYAGE_API_KEY` environment variable not set.

*Solution*:

[source,bash]
----
# Set environment variable
export VOYAGE_API_KEY='your-api-key-here'

# Or set in Python before import
import os
os.environ['VOYAGE_API_KEY'] = 'your-api-key-here'
----

==== Issue: Connection timeout to Cassandra

*Problem*: Cannot connect to Cassandra cluster.

*Solutions*:

* Verify Cassandra is running: `nodetool status`
* Check firewall rules allow port 9042
* Verify contact points are correct
* Check authentication credentials if enabled

== Advanced Use Cases

=== Multimodal Embeddings with voyage-multimodal-3.5 / voyage-multimodal-3

Voyage AI by MongoDB's multimodal models enable embedding text, images, and video in the same vector space, enabling powerful cross-modal search capabilities.

==== Model Comparison

[cols="1,2,2"]
|===
|Feature |voyage-multimodal-3.5 |voyage-multimodal-3

|**Modalities**
|Text + Images + Video
|Text + Images

|**Dimensions**
|256, 512, 1024 (default), 2048
|1024 (fixed)

|**Context Length**
|32,000 tokens per input, 320,000 tokens in total per request
|32,000 tokens

|**Image Limits**
|16M pixels, 20MB
|16M pixels, 20MB

|**Video Limits**
|20MB (requires voyageai >= 0.3.6)
|Not supported

|**Status**
|Recommended
|Legacy
|===

==== Model Capabilities

* **Unified Vector Space**: Text, images, and video share the same embedding space
* **Cross-Modal Search**: Text queries can find images/video, image queries can find text
* **Interleaved Content**: Support for documents with mixed text and images
* **Context Length**: 32,000 tokens per input; voyage-multimodal-3.5 accepts up to 320,000 tokens in total per request
* **Image Constraints**: Max 16 million pixels, max 20MB per image
* **Video Constraints**: Max 20MB (voyage-multimodal-3.5 only)
* **Pixel Pricing**: Every 560 image pixels = 1 token, 1120 video pixels = 1 token

[source,python]
----

text_embedding = text_result.embeddings[0]

# Embed image with caption (interleaved)
captioned_result = vo.multimodal_embed(

combined_embedding = captioned_result.embeddings[0]

# Using voyage-multimodal-3 (fixed 1024D, no output_dimension parameter)
legacy_result = vo.multimodal_embed(

    model="voyage-multimodal-3",
    input_type="document"
)
legacy_embedding = legacy_result.embeddings[0]  # Always 1024-dim

==== Cross-Modal Search Queries

**Text Query Finding Images:**

[source,python]
----
# User searches with text
query_text = "sunset over ocean"
query_vector = vo.multimodal_embed(
    inputs=[[query_text]],
    model="voyage-multimodal-3.5",

=== Contextual Embeddings with voyage-context-4

Voyage AI by MongoDB's `voyage-context-4` model generates contextual chunk embeddings that encode both local chunk details and global document context, significantly improving retrieval accuracy for RAG applications. (The previous-generation `voyage-context-3` remains accessible via the API.)

==== Model Capabilities

* **Global Context Encoding**: Each chunk embedding contains document-level context
* **Improved Disambiguation**: Better handling of chunks that need surrounding context
* **RAG Optimization**: Designed as drop-in replacement for existing pipelines
* **Flexible Dimensions**: 256, 512, 1024 (default), 2048
* **Batch Limits**: Max 1,000 inputs, 16K total chunks and 120K total tokens per request. Without auto-chunking each document must fit in the 32K-token context window; auto-chunking splits longer documents

==== Input Formats

The `contextualized_embed` API accepts `inputs` as `Union[List[List[str]], List[str]]`. This guide always lets the service chunk documents (`enable_auto_chunking=True`, `chunk_size=32_000`), which fixes the input format:

* **Documents** (`input_type="document"`): a flat `List[str]`, one whole document per string. The service chunks each document, embeds every chunk with the context of its document, and returns the chunk texts (`chunk_texts`) next to the embeddings. Store the returned chunk texts.
* **Queries** (`input_type="query"`): a flat `List[str]` of query strings, without auto-chunking.
* **Not supported with auto-chunking**: a pre-chunked `List[List[str]]` for documents. The API rejects it with `auto-chunking expects one string per document`, and so does the SDK. Pass the whole document as one string instead.
* Auto-chunking works only with `input_type="document"`. With `input_type="query"` or no input type the SDK raises a `ValueError` and the raw API returns a 400 error.

NOTE: `chunk_size` is 32,000, so the service splits a document only when it is longer than that. A short document comes back as a single chunk.

. **Pass Whole Documents**

=== Reranking with Voyage AI by MongoDB (Two-Stage Retrieval)

Voyage AI by MongoDB's reranking models (`rerank-3`, `rerank-3-lite`) enable sophisticated two-stage retrieval that significantly improves search accuracy. This approach combines the speed of Cassandra's vector search with the precision of cross-attention reranking. The previous-generation `rerank-2.5` and `rerank-2.5-lite` models remain available.

==== What is Reranking?

Reranking is the process of re-scoring and re-ordering initial search results using a more sophisticated model. While vector similarity search (cosine similarity) is fast and scales well, it has limitations:

* **Semantic Similarity ≠ Relevance**: Embeddings capture general similarity, not query-specific relevance
* **Single-Vector Compression**: Each document compressed to one vector loses nuance
* **No Cross-Attention**: Vector search doesn't directly compare query and document tokens

Reranking addresses these limitations by analyzing the full text of both query and candidates using transformer-based cross-encoders, providing much more accurate relevance scoring.

==== Two-Stage Retrieval Architecture

[source,text]
----
User Query
    ↓
[Stage 1: Cassandra Vector Search]
  Fast ANN retrieval → 100 candidates (10-50ms)
    ↓
[Stage 2: Voyage AI by MongoDB Reranking]
  Precise relevance scoring → Top 10 results (100-300ms)
    ↓
Final Results (Total: 150-350ms)
----

**Why Two Stages?**

* **Stage 1 (Speed)**: Cassandra quickly narrows millions of documents to ~100 candidates
* **Stage 2 (Accuracy)**: Voyage AI by MongoDB reranker precisely scores only the candidates
* **Best of Both**: Fast retrieval + accurate ranking = production-ready search

==== Python API Usage

[source,python]
----
import os
import voyageai
from cassandra.cluster import Cluster

# Initialize clients
vo = voyageai.Client(api_key=os.getenv("VOYAGE_API_KEY"))
cluster = Cluster(['127.0.0.1'])
session = cluster.connect('my_keyspace')

def two_stage_search(query: str, vector_candidates: int = 100, final_results: int = 10):
    """Perform two-stage retrieval: vector search + reranking."""

    # Stage 1: Generate query embedding
    query_embedding = vo.embed(
        texts=[query],
        model="voyage-4-lite",
        input_type="query",
        output_dimension=1024
    ).embeddings[0]

    # Stage 1: Cassandra vector search (retrieve candidates)
    vector_query = session.prepare("""
    SELECT
        doc_id, title, content,
        similarity_cosine(embedding, ?) as similarity_score
    FROM documents
    ORDER BY embedding ANN OF ?
    LIMIT ?
    """)

    rows = session.execute(
        vector_query,
        (query_embedding, query_embedding, vector_candidates)
    )

    # Convert to list for reranking
    candidates = [
        {
            "doc_id": str(row.doc_id),
            "title": row.title,
            "content": row.content,
            "vector_similarity": float(row.similarity_score)
        }
        for row in rows
    ]

    if not candidates:
        return []

    # Stage 2: Rerank with Voyage AI by MongoDB
    rerank_result = vo.rerank(
        query=query,
        documents=[c["content"] for c in candidates],
        model="rerank-3",
        top_k=final_results,
        truncation=True  # Handle long documents
    )

    # Combine reranking scores with original metadata
    final_results = []
    for item in rerank_result.results:
        original = candidates[item.index]
        final_results.append({
            "doc_id": original["doc_id"],
            "title": original["title"],
            "content": original["content"],
            "relevance_score": item.relevance_score,  # 0-1 scale
            "vector_similarity": original["vector_similarity"],
            "rank_improvement": item.index  # Original position
        })

    return final_results

# Usage
results = two_stage_search(
    query="How do I reset my password?",
    vector_candidates=100,
    final_results=10
)

for i, result in enumerate(results, 1):
    print(f"{i}. {result['title']}")
    print(f"   Relevance: {result['relevance_score']:.4f}")
    print(f"   Improved from position #{result['rank_improvement'] + 1}")
----
